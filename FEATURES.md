# Potential Features

Ideas for future KAthenaeum releases. KAthenaeum is meant for students: a tool for learning and for doing school work. Nothing here is committed to. Lift estimates take into account what the app already has (see CLAUDE.md). Each entry gives the user value, an estimated lift, what it can reuse, the new work it needs and the risks.

## In progress: the Classroom

An AI teacher that plans courses from the installed libraries (asked for by the user, 2026-10-20; one learner per
computer).

| Phase | What | State |
|---|---|---|
| 1 | Profile, ten core subjects and courses of your own, levels, syllabus planning, readings from the libraries, lesson introductions, progress, missing-library prompts | **Done in 0.14** |
| 1b | The lesson beside its readings; a course kept in a research project (readings, introductions, highlights) | **Done in 0.15** |
| 2 | Lesson quizzes and unit tests built from the readings (answers checked against the text), grading, progress per unit | **Done in 0.16** |
| 3 | A teacher to talk with on each lesson (guiding questions, not answers), review of weak spots | **Done in 0.16** |

Known limits: a 2B model plans sensible courses and explains well from a reading, but cannot be trusted to invent
material; maths practice problems need numbers generated by code, not by the model.

## Lift scale

The sizes assume one developer who already knows the codebase. Each one includes tests, handbook updates and a metainfo release note.

| Lift | Effort | Typical shape |
|---|---|---|
| **S** | 1–3 days | One page or dialog, no schema change |
| **M** | 1–2 weeks | A new core module or a database migration, one or two QML pages |
| **L** | 2–4 weeks | Several modules, or an AI pipeline with grounding |
| **XL** | 1–2 months | New subsystems, file formats or deployment modes |

## 1. Citations and bibliography (done in 0.13)

**Lift: M**

**What it is:** Each article gets a "Cite This Article" action that offers MLA 9, APA 7 and Chicago formats, with a copy button. Each project keeps a bibliography. A document or report can insert a works-cited list built from the sources it actually cites.

**Why it matters:** Students need citations in almost every assignment, and they are often unsure how to cite an offline copy of Wikipedia.

**Reuses:**
- ZIM metadata. `ZimArchive` already reads Publisher, and can also read Date, Title and Language.
- Project items (`project_items`), which already record the articles in a project.
- Export already turns article links into a References list naming each article and its library. Formatted styles replace that list.
- `Rag::attribute` and report renumbering in `drafts.cpp`, which already know which article each `[n]` refers to.

**New work:**
- A `src/core/citations.{h,cpp}` module for the formatters. It is pure functions, so it is easy to unit-test.
- Each citation should state the access method: "Wikipedia, offline copy via Kiwix, snapshot YYYY-MM" plus the original URL (`https://<lang>.wikipedia.org/wiki/<Title>`).
- A Cite dialog on `ArticlePage.qml`.
- A Bibliography tab in `ProjectPage.qml`.
- An "Insert Works Cited" action in the document editor.
- Reports end with a formatted bibliography instead of a bare source list.

**Risks:**
- Non-Wikipedia ZIMs (Gutenberg, Stack Exchange, PhET) need their own templates or a generic fallback.
- Article revision dates are not stored in a ZIM, so citations can only give the snapshot date.

## 2. Highlights and notes (done in 0.13)

**Lift: M**

**What it is:** A student selects text in an article and picks Highlight from the right-click menu, with a colour and an optional note. Highlights don't have to belong to a project. Every highlight and note is listed on a Notes page, by article, and in each project, with a link straight back to the passage.

**Why it matters:** This turns reading into research. The notes can also feed Ask and reports, so the AI works from what the student marked as important.

**Already there:**
- Saved excerpts (project clips) are already marked in their articles while rendering (`ArticleRenderer::render` wraps them in `<mark class="excerpt-hl">`, matching that ignores whitespace and case).
- Right-click "Save to Project…" already reaches the selected text.
- So this is mostly an extension of excerpts. It needs no JavaScript: the article view runs none, and should keep running none.

**New work:**
- A migration to v9: a `color` column on clips, and `project_id` made optional (or a `highlights` table with the same shape).
- Colour classes in the article CSS, readable in light and dark mode.
- A Highlight entry with colour choices in the right-click menu.
- A Notes page (sidebar, Research group) listing every highlight by article, with filters for colour and project.
- Export of the notes to a document as Markdown with citations (ties into #1).
- An option to put the project's highlights first in Ask's context.

**Risks:**
- Updated articles can change or remove a passage. The Notes page must show "no longer in the article" notes instead of dropping them silently.
- The right-click menu is already busy (Copy, Ask About This, Save to Project). A Highlight submenu keeps it short.

## 3. Flashcards and quizzes

**Lift: L**

**What it is:** "Make Study Cards" works from an article, a project or a set of highlights. Cards are reviewed with spaced repetition (SM-2 or FSRS). A Quiz mode asks multiple-choice or short-answer questions and shows the source passage after each answer.

**Why it matters:** Students already make study cards for tests, and retrieval practice is one of the best-supported ways to learn.

**Reuses:**
- `Rag` passage picking.
- The Ollama client.
- The attribution check from reports, used to reject cards the source doesn't support.

**New work:**
- A `src/core/study.{h,cpp}` module with these steps:
  - A card-generation prompt that asks for JSON output, then parsing and validation.
  - A grounding check that rejects any card whose answer the passage does not support.
  - The review scheduler.
- A migration with `decks` and `cards` tables: front, back, source article and passage, due date, ease, interval.
- A Study page with the review session and keyboard shortcuts (1–4 to grade a card).
- A Quiz page, and making distractors (wrong options) for multiple-choice questions.
- Export to Anki (`.apkg`) or CSV, as a nice-to-have.

**Risks:**
- Quality with small models (`qwen3.5:2b`). Wrong cards are worse than no cards, so grounding and the student's ability to edit or delete a card are required.
- Generation time. Run it in the background, with progress, like reports.

## 4. Checking a draft against its sources

**Lift: M**

**What it is:** A "Check My Draft" action in the document editor runs on the student's own writing, with three results:
- Sentences no project source supports are flagged.
- Sentences too close to a source's wording are flagged with "you may need to quote or paraphrase this."
- Each supported claim gets a link to its source, with an offer to insert a citation, which ties into #1.

**Why it matters:** This teaches academic honesty and research skills instead of only catching plagiarism, and it catches mistakes before a teacher does.

**Reuses:**
- The `Rag::attribute` and `[?]` flagging logic in `drafts.cpp`, which already does nearly this for AI text.
- The embeddings.
- The document editor (KTextEditor), whose marks or inline notes can show the results.

**New work:**
- An overlap detector: shingled n-gram matching against the retrieved passages, plus a similarity threshold.
- A results panel in the editor, with jump-to-sentence and the matching source passage side by side.
- Settings for strictness.

**Risks:**
- False positives on common phrases and proper nouns. Tune the n-gram length and ignore quoted text.
- It must be clear that this only checks against the student's local sources. It is not a full plagiarism service.

## 5. Tutor mode for Ask

**Lift: S–M**

**What it is:** A switch on Ask that changes it from answering to tutoring. It replies with guiding questions, points the student to the paragraph that holds the answer, and confirms or corrects the student's own answer. A parent or teacher can lock it on (see #12).

**Why it matters:** Teachers are much more likely to accept a tool that helps students think than one that hands them the answer.

**Reuses:**
- `Answerer`, `Conversation` and `ChatView` unchanged, apart from the prompt and a per-chat mode flag.

**New work:**
- The tutor system prompt.
- A `mode` column on `chats`.
- A mode toggle in the chat header.
- A "Check my answer" quick action.
- The Lift is S without locking, M with the lock.

**Risks:**
- Small models drift back into giving answers, so it needs prompt testing and maybe a post-check.

## 6. Dictionary lookup (done in 0.13)

**Lift: M**

**What it is:** A student selects a word in an article and picks Define from the right-click menu. A popover shows the definition, pronunciation and part of speech from an installed Wiktionary ZIM, with a link to the full entry.

**Reuses:**
- The ZIM reader and title lookup (Wiktionary titles are the words).
- The catalog, for suggesting the Wiktionary download.
- The right-click menu that Ask About This already uses.

**New work:**
- Finding which installed library is a dictionary (by ZIM name or tags).
- An extractor that pulls the first sense for the article's language out of Wiktionary HTML.
- Case and inflection fallbacks ("Ran" → "ran" → "run").
- The popover.

**Risks:**
- Wiktionary's HTML structure differs by language edition, so start with English only.
- Double-click lookup would need JavaScript in the article view, which is off by design. Keep it to the right-click menu.

## 7. Show on map from articles (done in 0.13)

**Lift: S–M**

**What it is:** Articles about a place get a "Show on Map" button that opens the map at that place. This is the reverse of map click → article.

**Reuses:**
- `map_places`, which already links OSM places to Wikipedia titles, so the reverse lookup is a query.
- `MapManager`.
- The flyTo code in `MapPage.qml`.

**New work:**
- A `MapPlaces::byTitle` lookup and an index on the title column.
- A button on `ArticlePage.qml` that appears only when a downloaded region contains the place. That version is S.
- A fallback that parses `{{coord}}`/geo microformat spans (`.geo-dec`) out of the article HTML for places outside the downloaded data. That version is M.

**Risks:** Few. If the place isn't in any downloaded region, offer to download a region.

## 8. Timelines (done in 0.17)

**Lift: L**

**What it is:** A tool that pulls dates and events out of an article or a whole project into a scrollable visual timeline. Each event links back to its passage, and the timeline exports to a document.

**Reuses:**
- Rag passages.
- Ollama, for extracting events as structured output.
- Attribution, for grounding.
- Projects.

**New work:**
- Date extraction. Use a deterministic regex pass for years and full dates, plus the LLM for event phrasing.
- Normalising dates, including BCE, "circa" and ranges.
- A timeline QML component with zoom and grouping by article.
- Saving timelines to the project.

**Risks:**
- Date ambiguity and historical calendars.
- Rendering performance with hundreds of events.

## 9. Reading level

**Lift: S**

**What it is:** Selecting a passage offers "Explain Simpler." It rewrites the passage for a chosen grade level, with the original shown next to it and a reminder to cite the original article, not the rewrite.

**Reuses:**
- Ollama.
- The right-click menu on selected text, as Ask About This uses it.

**New work:**
- A prompt with a grade setting.
- A side panel or dialog.
- A preferred grade level in Settings.

**Risks:** Simplification can change meaning, so always show the original next to it.

## 10. Student starter pack

**Lift: S**

**What it is:** A curated one-click bundle in the Library Manager. It holds Wikipedia (sized to the disk), Wiktionary, Wikibooks, Project Gutenberg, PhET simulations and other education ZIMs from the Kiwix catalog, with the total size shown before download.

**Reuses:** The catalog feed and downloads queue.

**New work:**
- A bundled pack definition (JSON listing catalog names and flavours).
- A pack card in `CatalogView.qml`.
- A first-run suggestion on the empty Libraries page.

**Risks:** Catalog names change over time. Match by name prefix and fail gracefully.

## 11. Classroom bundles and shared libraries

**Lift: XL**

**What it is:**
- **Project bundles:** a teacher exports a project (reading list, notes, highlights, documents, map region) as a single `.kathenaeum` file, and students import it.
- **Shared libraries:** point KAthenaeum at a read-only network share or USB drive of ZIMs and map regions. This lets a school without internet provision a whole lab from one copy.

**Why it matters:** The offline design is KAthenaeum's strongest selling point for schools with limited or filtered internet.

**Reuses:** Projects, the library folder setting, and map regions stored as local files.

**New work:**
- A bundle format: a zip with a manifest, versioning, and import conflict handling.
- Support for several library roots, including read-only roots.
- Map regions stored on a share.
- Documentation for IT administrators.
- Optionally, system-wide defaults in `/etc/xdg`.

**Risks:**
- Scope creep. Ship bundles first and shared libraries second.
- Read-only media breaks assumptions in downloads, updates and removal.

## 12. Content and safety settings

**Lift: M**

**What it is:** A settings section, protected by a password, where a parent or teacher can:
- hide individual libraries
- lock tutor mode (#5)
- turn off AI writing (reports) or Ask entirely
- turn off catalog downloads.

**Reuses:** `AppSettings` and the existing gating of pages and actions in QML.

**New work:**
- A password hash in settings.
- A lock UI.
- Enforcing the locks in controllers, not only by hiding things in QML.
- Optionally, a system-wide policy file for managed machines.

**Risks:**
- A local password is easy to get around for a determined user with file access. Document this as a guard rail, not real security.
- Age-based content filtering of Wikipedia itself is out of scope. Point instead to Kiwix's curated selections, such as Wikipedia for Schools.

## Suggested order

Citations (#1), highlights and notes (#2), the dictionary (#6) and show on map (#7) shipped together in 0.13.0. The
original plan is kept below for the rest.

1. **0.13:** citations (#1), show on map (#7), starter pack (#10), then begin highlights (#2). These are the lowest-risk, highest-use features.
2. **0.14:** finish highlights (#2), flashcards (#3), draft check (#4), tutor mode (#5) and reading level (#9). Together these make up the "study" release, sharing the grounding work.
3. **0.15:** timelines (#8). Dictionary (#6) can come with 0.14 if a Wiktionary ZIM extractor proves simple.
4. **1.0:** classroom bundles (#11) and safety settings (#12). These are what make KAthenaeum suitable for schools.

## Dependencies

- #4 Draft check → is better with #1 Citations, to insert citations.
- #12 Safety settings → locks #5 Tutor mode.
- #3 Flashcards → can use #2's highlights as card sources.
